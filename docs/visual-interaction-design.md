# Visual and interaction design

Jason's enduring preference is to receive information visually and interact with controls that feel tangible: "538 meets Apple," with the energy of an amusement park or casino. Apply this to Data Dawgs interfaces, design proposals and AI explanations produced for this repository. Favor abundant useful visuals over walls of prose, while keeping the analysis legible and the underlying data honest.

## Visual language

Preserve the dark Data Dawgs foundation and high-contrast Dawg Orange. Use compact charts, comparison cards, project and milestone boards, and clear relationships to make decisions easier. Pair charts with readable labels, dates, units and accessible text or tables. Color must not be the only signal. Whitespace and hierarchy should keep a dense view readable rather than turn it into decoration.

Show real vote visualizations only when vote records exist, with their actual count and scope. Do not invent participation, online agents, progress percentages, milestones or execution status. Show unavailable fields explicitly. Label synthetic examples and keep private records out of public source, fixtures and screenshots.

## Tactile controls

Where a real adjustable value or action exists, use weighted-looking jog dials, sliders, levers and switches with clear travel, visible selection and crisp pressed feedback. Give each control a meaningful purpose; do not add pretend knobs to static information. Display exact values and provide keyboard operation or a conventional equivalent. Preserve native semantics, visible focus and touch targets that work on small screens.

Immediate input feedback may acknowledge a press or pending request. Success feedback must wait for a verified result; a stored working status does not prove execution. Never celebrate a failed, pending or merely proposed action.

Audio is opt-in and easy to mute. Respect reduced-motion preferences with static or minimal transitions. Avoid flashing, autoplay sensory effects, manipulative engagement loops and rewards unrelated to completed work. Tactility should support control and understanding.

## Mobile priority

Put decisions and useful controls above the fold. Keep branding compact. Use stacked cards and readable charts that fit 320/390 px widths without requiring precision gestures or horizontal scrolling for core work. Open long context documents on demand. Preserve ordinary navigation and accessible dialogs.

For Data Dawgs Dispatch, prioritize decisions needing Jason, project summaries, stored task states, dependencies and last verified activity, subject to the actual schema. Unavailable capabilities remain visibly unavailable. Keep discussion and full context secondary. Offer a daily brief or podcast only when its data and destination exist.

## Review criteria

Check that each visual answers a real question and each control changes a real supported value or action. Verify data provenance, empty states, unavailable fields, keyboard/focus behavior, reduced motion, contrast, mobile layout and pending/error/success feedback. Use synthetic fixtures for screenshots. This design direction does not itself approve schema changes, deployment, new agents, permissions or account-level instruction edits.
