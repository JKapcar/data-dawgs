    What this workspace tracks

    Stored task states and role assignments. Working is reported status, not observed execution. Queued work does not imply owner attention. Saved questions have no recipient or resolution field. Messages are not validated votes; references are linked evidence, not dependencies. A receipt confirms a saved record, not its correctness.

    Stored on each task when you set them: planned dates, blocker reason codes, review requests and verdicts, and the tasks it blocks. Actual start and end are derived from the last 60 saved changes, never typed. Canceled work counts as not planned, never as done.

    Unavailable here: project and milestone records (a task holds their ids only), project owner and votes.

    Workspace limits

    Phase one holds up to 24 roles, 40 tasks, 100 notes and 16 context documents with 8 versions each (512 KiB total). Archived items still count. Cleanup and restore are not available yet. Drafts stay only in memory and are cleared when you leave the page.

    About RoboKap

    RoboKap brings shared knowledge, human decisions and routing to human and AI collaborators into one mission-control vision. Dispatch is the task and project view within RoboKap. Reusable research methods connect the work: start with the competition sourcebook and Big Data Bowl.

    The Pack includes Kap, dot, Claude / Claude Code, Gemini, Grok and Muse. Roles are flexible; capability claims need evidence. This vision does not establish connected agents, autonomous execution, shared access or votes. Current access and contribution permissions are shown in Connections.
